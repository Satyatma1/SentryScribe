Final-year BTech project · Computer vision + LLM

SentryScribe

CCTV footage in, searchable incidents out. Pretrained YOLOv8 and ByteTrack follow every person, car and bag; a rule engine turns their tracks into timestamped events; an LLM writes the incident report and answers questions, citing only those events.

    Pipeline

    Five stages, two halves

    The vision half runs once per video and writes events to a database. The language half runs on demand and can only read those events, so every sentence it writes traces back to a row.

    1. 1

      Frame sampler

      Decodes the video and keeps about 10 frames per second.

      OpenCV
    2. 2

      Detector

      Finds people, vehicles and bags in each frame, pretrained, no training.

      YOLOv8 · COCO
    3. 3

      Tracker

      Links detections over time so each object keeps one ID.

      ByteTrack
    4. 4

      Event engine

      Zones, lines and timers turn tracks into six event types, with noise handling.

      rules + hysteresis
    5. 5

      LLM layer

      Writes cited incident reports and answers questions through four search tools.

      Qwen2.5 · local · tool use

      LLM layer

      Grounded by construction

      The model never sees video. It receives the event log, must cite an event ID for every claim, and a validator checks each citation against the database before a report is accepted.

      1 · What the model receives

      // one row of the event digest (example)
{"id":"E14", "type":"ZONE_INTRUSION",
 "object":"truck", "zone":"Gate B",
 "start":"00:02:31", "end":"00:02:43",
 "tracks":[57], "conf":0.81}

      About 30 tokens per event, so a long video fits in one prompt.

      2 · What it can call

      search_events(type, object_class, zone, t_from, t_to)
count_objects(object_class, zone, t_from, t_to)
get_event(event_id)
video_summary(video_id)

      Typed, parameterised functions. The model never writes SQL.

      3 · What gets rejected

      "Intrusion at 00:00:07 [E99]."
→ unknown_ids: ["E99"], valid: false
→ regenerate once with the error
"Intrusion at 00:00:07 [E1]."
→ valid: true

      Unit-tested, and run on real footage: all nine incident reports passed. Q&A answers are graded automatically against the event log.
